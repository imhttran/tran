# Rust migration — dependency decisions

Established libraries are preferred over hand-written infrastructure. This
record states what is retained, what was adopted, and what is selected for the
remaining migration tasks, with the toolchain constraint and the verification
behind each. Decision-only for the deferred items: they are added to
`rust/Cargo.toml` when the task that uses them lands, so the manifest never
carries a dead dependency.

- Toolchain: `rust/rust-toolchain.toml` pins `channel = "1.99.1"` (edition 2021).
  Every version below is chosen to build on that pinned toolchain.
- Guardrail: no large RAG framework. Only infrastructure and leaf libraries.

## Adopted now (used by current code)

| Crate | Version / features | Replaces | Why |
| --- | --- | --- | --- |
| `reqwest` | `0.12`, `default-features = false`, `["blocking", "rustls-tls"]` | hand-rolled `std::net` HTTP/1.1 POST in `src/bin/smoke.rs` | Established HTTP client; `rustls-tls` avoids a system OpenSSL dependency; `blocking` preserves the current synchronous pipeline. |

`reqwest` sits behind the existing `ollama::Transport` trait, so the mock
transports in tests (and the timeout/cancellation behavior above the transport)
are unchanged. A non-2xx status is still returned as `Ok((code, text, body))`,
a transport failure as `Err(String)`, and redirects are not followed — matching
the transport it replaces.

## Markdown / PDF adoption gate

Adopt a Markdown or PDF library **only after fixture checks confirm section
boundaries, text, and page provenance** against the Go baseline
(`rust/fixtures/`, and the Go `internal/loader` / `internal/chunking` outputs):

- The current `## ` section parser is hand-rolled specifically to match the Go
  baseline's section semantics; a full Markdown AST library (`pulldown-cmark`)
  is a **candidate to evaluate**, not a swap — it may change section boundaries.
- `lopdf` text extraction is likewise kept until page-provenance parity is
  demonstrated (one section per page, 1-based page numbers, scanned-PDF
  rejection).

## Non-goals

- No large RAG framework, and no replacement of the pipeline with one.
- No changes to the Go reference behavior; library adoption preserves the wire
  contracts (`OLLAMA_*`, `DATABASE_URL`, the `rag-retrieval/v1` JSON schema).
